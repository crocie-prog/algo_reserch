## 3. Отсечение по издержкам (ex-ante, без доходности)

Показатели (этап 3): cost_to_target (S1, S5, S6) = 2·(fee + slippage) /
медиана цели сделки; cost_to_width (S3) — к ширине канала; cost_to_band (S4) —
к m·ATR/close.

**Предложение: порог 0.2 для всех трёх показателей.** Конфигурация с
показателем > 0.2 на train-окне фолда (для данной пары) исключается до
ранжирования.

Обоснование без доходности:
- Для контртренда цель T — путь до выхода. Если сделка симметрично
  выигрывает или проигрывает T, то при издержках c безубыточная доля удачных
  сделок равна p* = (1 + c/T)/2. Порог 0.2 соответствует p* = 60%, порог
  0.1 — 55%, 0.5 — 75%. Требование выше 60% удачных сделок для 1h
  контртренда нереалистично без информации, которой у нас нет.
- Для тренда (S3, S4) знаменатель — расстояние до разворота, то есть риск
  сделки R. Издержки свыше 0.2·R на каждую сделку при доле удачных сделок
  тренда 35–45% съедают преимущество асимметрии выплат. На текущих сетках
  порог не связывающий (наблюдалось 0.009–0.08) и защищает от вырожденных
  узких каналов.
- Порог не настраивается под результат. По описательному прогону этапа 3
  (train) он исключает S6 при k = 1.5, e = 0.5 на BTC и ETH (0.45–0.55;
  у BTC с 2022 года — 0.72) и частично при k = 2.0. S1 при
  z_entry − z_exit = 1.5 проходит на всех окнах (0.03–0.16). При
  z_entry − z_exit = 0.5 показатель втрое больше, и короткие окна
  (w = 24, 0.26–0.48) исключаются.

Исключённые по этому правилу конфигурации не ранжируются и в журнал DSR
не пишутся (их доходность не считается).

## 4. Фолды, ранжирование, ансамбль

**Фолды.**
- Схема expanding (основная): train = [usable_from, val_start),
  валидация — календарный квартал. Шаг — квартал. Первый фолд — когда train
  ≥ 12 месяцев; последний квартал валидации — 2023Q4.
- Фолдов: BTC 8 (2022Q1–2023Q4), ETH 7 (2022Q2–2023Q4), SOL 4 (2023Q1–2023Q4).
- Схема rolling (чувствительность): train = 12 месяцев перед val_start.
  Отдельный вариант, отдельная попытка DSR.
- `folds()` без `allow_test` не создаёт окон после 2023-12-31.

**Ранжирование.** Для каждого фолда, стратегии и пары отдельно:
1. Исключение по §3 (издержки) и по частоте: trades_per_year на train ниже
   min_trades — 1h: 12, 15m: 24. Оставшиеся — N_pass конфигураций.
2. Метрика — годовой Sharpe на train-окне по чистой доходности (комиссия,
   funding, slippage данного прогона §5; rf = 0), аннуализация √(365·24)
   для 1h.
3. top-k = min(10, ⌈N_pass/4⌉). При полной сетке: S1 → 10, S3 → 3, S4 → 5,
   S6 → 4, S5 → 1 (ансамбля нет).
4. Ансамбль: позиция = среднее sign(pos) по top-k.
5. Отказ от торговли: торговать в фолде, только если train-DSR лучшей
   конфигурации ≥ 0.5 (§8, уровень 1: N_eff сетки этого фолда). Иначе
   позиция в квартале валидации 0. DSR ≥ 0.5 ⇔ лучший train-Sharpe не ниже
   ожидаемого максимума Sharpe из N_eff независимых нулевых стратегий.
   Обоснование: фиксированный порог (0.3 или t ≥ 1) на максимуме из N
   конфигураций проходит и на чистом шуме. N_pass = 0 — не торгуем.
6. S5 (N_pass ≤ 1): N_eff = 1, ожидаемый максимум 0; правило сводится
   к PSR(0) ≥ 0.5, т.е. train-Sharpe > 0.

**Сшивка валидации.** Позиции кварталов склеиваются в один OOS-ряд на
пару; движок прогоняется по сшитому ряду. Смена ансамбля на границе
квартала облагается комиссией, позиция до usable_from обнуляется.

**Центр плато (альтернатива, отчётная).** Train-Sharpe сглаживается по
соседям в сетке (среднее по окрестности ±1 шаг по каждому параметру, на
краях — по имеющимся соседям). Выбирается argmax сглаженного; правило
отказа то же. Основной вариант — ансамбль top-k; центр плато — отдельная
попытка DSR, показывается рядом.

## 5. Чувствительность к slippage

Единый прогон для S1, S3, S4, S5, S6 при slippage_per_side ∈
{0, 0.0005, 0.001}. Отбор переделывается при каждом значении (издержки
влияют на ранжирование). Основной — 0. Прогоны с 0.0005 и 0.001 — **не
попытки**: из них не выбирают, в журнале пометка «sensitivity», в N не
входят. Вывод о стратегии считается устойчивым, только если знак
OOS-Sharpe сохраняется при 0.0005.

Дополнительно S6: вариант с train-окнами не раньше 2022-01-01 (вопрос
объёма 1m за 2021) — попытка (§8). Валидация всех пар и так
начинается не раньше 2022Q1.

## 6. Что выводится

**По каждому фолду × стратегии × паре (1h и 15m):**
- размер сетки; исключено по §3 и по min_trades;
- N_pass, N_eff фолда (уровень 1), лучший train-Sharpe, ожидаемый максимум
  Sharpe, train-DSR; торговали или нет; выбранные параметры top-k;
- валидация ансамбля: Sharpe, годовая доходность, MDD, экспозиция,
  сделок в год, оборот, издержки (комиссия, slippage, funding);
- то же для центра плато;
- данные тепловых карт train-Sharpe: S1 (w × z_entry при каждом z_exit),
  S4 (m × n), S6 (k × e);
- точки для scatter «train-Sharpe vs val-Sharpe» (по всем конфигурациям
  сетки, не только top-k).

**Итог по стратегии × паре × ТФ (сшитый OOS):**
- метрики табл. 5; Sharpe с SE по Lo (2002) с q = ⌊T^{1/4}⌋ лагов (T —
  число баров);
- DSR с N_eff уровня 2 (§8), с асимметрией и эксцессом OOS-ряда;
- доля фолдов без торговли (train-DSR < 0.5) — обязательная метрика;
- доля фолдов с положительным val-Sharpe (среди торговавших);
- ранговая корреляция Спирмена train-Sharpe vs val-Sharpe по фолдам

- сравнение ансамбль vs центр плато; таблица чувствительности к slippage.

**Сводно по стратегии:** EW трёх пар — описательно, без весов (агрегация —

## 7. Критерии (зарегистрированы заранее)

Для стратегии на 1h, slippage 0, схема expanding, ансамбль top-k:

| Вердикт | Условие |
| --- | --- |
| Значимо | EW-OOS Sharpe > 0, t по Lo ≥ 2 и DSR (N_eff уровня 2, §8) ≥ 0.95 |
| Кандидат | EW-OOS Sharpe > 0; знак сохраняется при slippage 0.0005; val-Sharpe > 0 больше чем в половине фолдов хотя бы на двух парах из трёх |
| Нет | иначе |

- «Кандидат» и «значимо» переходят на этап 6 (сравнение схем CV); «нет» —
  дальше не оптимизируется и не перепроектируется по результатам валидации.
- Ожидание, записанное заранее: при OOS ~2 лет (BTC) SE годового Sharpe
  ≈ 0.7, поэтому «значимо» маловероятно. Отрицательный или незначимый итог —
  тоже результат, он фиксируется.
- Мало сделок: если на OOS у пары < 30 сделок, вердикт для этой пары —
  «недостаточно данных», без дальнейшей оптимизации.
- 15m: та же таблица отдельно. Расхождение выводов 1h и 15m фиксируется, но
  не используется для выбора.

## 8. Попытки и N_eff для DSR

**Попытка — то, из чего выбирается.**

| Что | Попытка? |
| --- | --- |
| Схема фолдов rolling (против expanding) | да |
| Правило выбора «центр плато» (против ансамбля top-k) | да |
| S6 с train-окнами с 2022-01-01 | да |
| Альтернативы границы дня S5/S6 (A, C), если прогоняются | да |
| Прогоны slippage 0.0005 и 0.001 (§5) | нет — «sensitivity», в N не входят |
| 15m (§7: не используется для выбора) | нет |
| Конфигурации сетки внутри фолда | учитываются на уровне 1 |
| S2 | не участвует |

**Уровень 1 — выбор конфигурации в фолде (правило отказа, §4 п. 5).**
- Набор: N_pass конфигураций фолда и пары.
- N_eff = число собственных значений корреляционной матрицы чистых
  train-доходностей этих конфигураций, объясняющих 95% её следа
  (консервативно: participation ratio (Σλ)²/Σλ² занижает N и сдвигает DSR
  в сторону прохода; она выводится как нижняя граница).
- Ожидаемый максимум: SR₀ = √V · [(1 − γ)·Φ⁻¹(1 − 1/N_eff) +
  γ·Φ⁻¹(1 − 1/(N_eff·e))], γ — постоянная Эйлера–Маскерони; V —
  выборочная дисперсия train-Sharpe (на бар) N_pass конфигураций; при
  N_eff = 1 SR₀ = 0.
- train-DSR = PSR(SR₀) лучшей конфигурации с её асимметрией, эксцессом
  и числом баров train.

**Уровень 2 — вердикт по OOS (§7).**
- Набор попыток (1h): S1, S3, S4 — {expanding, rolling} × {ансамбль,
  центр плато} = по 4; S5 — {expanding, rolling} = 2; S6 — 4 + 4 (с 2022) = 8.
  **Итого 22 попытки** (плюс альтернативы границы дня, если прогоняются).
- Ряд попытки — сшитая OOS-доходность EW трёх пар.
- N_eff — тем же методом (95% следа) по корреляционной матрице этих
  OOS-рядов; V — дисперсия их OOS-Sharpe. DSR для «Значимо» (§7) — с этим
  N_eff.
- Множественность по конфигурациям сетки на уровне 2 не учитывается
  повторно: отбор конфигураций шёл на train, валидация — вне выборки.
- Почему 22, хотя на test (§9) идёт только основной вариант: §0 п. 4
  допускает новый вариант после просмотра результатов. 22 попытки заранее
  учитывают цену такого переключения на альтернативу — в N входят все
  варианты, на которые мы смотрим и на которые можем переключиться.

**Оценка N_eff до запуска (прокси уровня 1, без доходности).** Корреляция
ПОЗИЦИЙ конфигураций полной сетки, 1h, train от usable_from:

## 9. Тестовый период и holdout

1. Test 2024-01-01 — 2025-12-31 открывается **один раз** — после фиксации
   всего конвейера на train. Порядок до test:
   1. этап 5 — вердикты §7 по стратегиям (коммит вердиктов);
   2. этап 6 — сравнение схем CV (expanding / rolling, purged K-fold,
      CPCV + PBO) на train и выводы по ним (коммит);
   3. этап 7 — правила МСП (уровни пара → стратегия → МСП, схема весов,
      неттинг) на train (коммит);
   4. датированная запись в «Изменениях» о фиксации конвейера;
   5. одно открытие test, которое проверяет и отдельных кандидатов,
      и МСП. На test прогоняется только зафиксированный конвейер:
      основной вариант протокола (expanding, ансамбль top-k, slippage 0,
      если этап 6 не зафиксировал иное до test), стратегии с вердиктом
      «Кандидат» или «Значимо». Результат фиксируется, дизайн после этого
      не меняется.
2. Если ни одна стратегия не получила «Кандидат» или «Значимо», test
   **не открывается** и сохраняется для следующих гипотез (RM, фильтры,
   прогнозы волатильности). Это фиксируется датированной записью
   в «Изменениях».
3. Holdout 2026-01-01 и позже — только после test, тем же порядком.
4. До этого `load()` их не отдаёт: без `allow_test` данные обрезаются на
   2023-12-31 (PeriodAccessError при запросе дальше); с `allow_test` —
   на 2025-12-31; доступа к 2026 в коде нет, он добавляется отдельным
   изменением после test.
