## 2. Конвейер подхода A (дневки, `stage3_walkforward.py`)

1. **Данные**: дневные OHLCV 17 акций MOEX (`load_data`), ключевая ставка ЦБ
   (`KR_PATH`), календарные дни между барами `cal_days` (`prepare_ticker_data`, 528–593).
2. **Доходность**: `lr[t] = log(close[t+1]/close[t])`, позиция `pos[t]`
   выставляется на закрытии t → `pnl[t] = pos[t]·lr[t]`. Это эквивалент
   `pos.shift(1)·ret` (`stage3_walkforward.py:549–550`,
   `strategies_walkforward.py:2703–2704`). Смещения на бар здесь нет.
3. **Индикаторы на всей истории** (`compute_base`, `strategies_walkforward.py:353–393`):
   ATR14, ADX14, SMA объёма 5/20, `vol_regime = ATR14/SMA50(ATR14)`, число
   красных/зелёных свечей за 5 баров, ширина Боллинджера и её скользящий
   30%-квантиль (окно 252, min 50), наклон SMA20 за 10 баров, фильтр
   `vf_pass = volume ≥ 0.5·SMA20(volume)`. Все — скользящие, без заглядывания.
4. **Сигналы** — события входа (+1/−1/0) и массивы выхода (`gen_s1..s6_signals`, 607–880).
5. **Движок** — машина состояний с риск-менеджментом (`bt_contrarian_v3`,
   `bt_trend_v3`, `bt_range_v3`, 887–1396): вход по close[t] только из флэта,
   переворота по встречному сигналу нет; выход по SL/TP/трейлу/max_hold/сигналу выхода.
6. **Walk-forward по годам**, перебор сетки «сигнал × RM» на train, топ-10,
   ансамбль, порог отказа (§4).
7. **Сохранение позиций** тестовых лет → `wf_positions_A.parquet` (1491–1514).
8. **Агрегация** пара → стратегия → МСП (§5), метрики (§6), корреляции,
   бутстрап, CE, графики.

## 3. Сигналы S1–S6 (финальные, `strategies_walkforward.py`)

Общее: на прогреве `sig[:WARMUP] = 0`, WARMUP = 200 дневных баров,
1800 часовых (`48`, `98`). У S3/S4 прогрев всегда 200 даже на часовиках
(`750`, `770`) — несогласованность. Позиция — результат движка, а не сам сигнал.

### S1 Mean Reversion (Z-score), 607–662

- `z = (close − SMA_w)/STD_w` (ddof=1, std снизу ограничен 1e-12).
- Вход long: `z < −z_entry`, short: `z > z_entry`.
- Фильтры (если `relaxed_filters=False`): `vol_regime < 1.2`; для long ≥3
  красных свечей из 5 (short — зелёных); объём ниже SMA5(объёма); `vf_pass`.
  При `relaxed_filters=True` — только `vf_pass`.
- «Сила сигнала» (`strength_threshold > 0`): среднее расширяющихся
  перцентильных рангов пяти метрик (|z|, |close−SMA|/ATR, |RSI−50|/50,
  объём/SMA20, ATR/SMA20(ATR)); вход отбрасывается, если ниже порога.
- Выход: `|z| < z_exit`.
- В `stage3_walkforward.py` есть своя упрощённая `gen_s1` с z = (close−MA)/ATR
  и MA-типами sma/ema/dema/hull/kama (273–278), но в финальном `walkforward_A`
  используется версия из `strategies_walkforward.py` через `dispatch_signals`.

### S2 Bollinger, 664–730

- Полосы `SMA_w ± k·STD_w`; long при `close ≤ lower`, short при `close ≥ upper`.
- Те же фильтры и «сила» (метрики: |%b−0.5|, ширина/SMA, объём, ATR-ratio, RSI).
- Выход: пересечение close через SMA (с любой стороны).
- По сути S1 с порогом выхода 0 и выходом по пересечению средней — сильная
  корреляция с S1 ожидаема.

### S3 Donchian, 732–753

- Канал `HH_w = max(high, w)`, `LL_w = min(low, w)` **сдвинут на 1 бар**
  (`prev_hc = hc[t−1]`) — корректно.
- Long: `close > HH_w[t−1]`, short: `close < LL_w[t−1]`.
- Фильтры: ADX14 > 20, объём > SMA20(объёма), `vf_pass`; на часовиках ещё
  дневной тренд SMA50 > SMA200 предыдущего дня (`align_daily_to_hourly`, 547–554).
- Выход long: `close < LL_w[t−1]`, short: `close > HH_w[t−1]`.

### S4 Supertrend, 301–328, 755–773

- `ATR` = **простая SMA от TR** (`calc_atr`, 248–256), не Уайлдер. ADX — по Уайлдеру.
- Базовые полосы `hl2 ± m·ATR`, рекурсия финальных полос стандартная
  (сравнение с close[t−1]).
- Вход: пересечение close через линию Supertrend (`close > st` и
  `close[t−1] ≤ st[t−1]`), фильтры ADX > 20, `vf_pass`, на часовиках — дневной тренд.
- Выход: обратное пересечение.

### S5 Pivot Points, 470–534, 790–851

- Уровни из H/L/C **предыдущего бара** (дневки) или предыдущего торгового дня
  (часовики, `searchsorted(..., side="right") − 1` по дате бара → строка
  текущего дня, у которой уровни уже построены по вчерашнему HLC). Корректно.
- Варианты: classic, fibonacci, woodie, camarilla; уровни 1/2/3.
- `pivot_frac`: уровень сдвигается к P: `P + f·(S − P)`.
- Long: `close < S_adj`, short: `close > R_adj`.
- Фильтр ATR-перцентиля: порог — перцентиль ATR **на первых WARMUP барах**
  (818–824), то есть фиксирован по самому началу истории.
- Дневки: «range-фильтр» (ADX < 25, ширина BB < её 30%-квантиля, |наклон SMA20| < 1%,
  `vol_regime < 0.9`) + `vf_pass`. Часовики: ADX < `adx_thresh` + `vf_pass`.
- Выход: пересечение close через P.

### S6 VWAP, 421–467, 853–880

- Скользящий VWAP по окну w: `Σ(tp·vol)/Σvol`, `tp = (H+L+C)/3`;
  `dev = rolling std(close − VWAP, w)`.
- Сессионный VWAP (часовики, `vwap_window = 0`): сброс накоплений на смене
  календарной даты метки бара; `dev` — std отклонений с начала сессии,
  на первом баре сессии = |close − VWAP| (≈0, ограничено 1e-8).
- Long: `close < VWAP − k·dev`, short: `close > VWAP + k·dev`.
- Фильтры как у S5. Выход: `|close − VWAP| < exit_mult·dev`.

## 4. Walk-forward, отбор, ансамбль, порог, RM

### Схема (`stage3_walkforward.py::walkforward_A`, 633–811)

- Окно **расширяющееся**: train = `[WARMUP, 1 января test_year)`,
  test = календарный `test_year`. Шаг — год. Тестовые годы 2022–2025 (`TEST_YEARS`).
  В README подход A заявлен «с 2020 года» — это версия `strategies_walkforward.py`
  (`A_TEST_YEARS = 2020..2026`), где разбиение сломано (§8).
- Бэктест на train гоняется от WARMUP до `train_end`; на test — от WARMUP до
  `test_end` целиком, т.е. состояние позиции переносится через границу train/test.
- Индикаторы считаются один раз на всей истории — допустимо, все они каузальные.

### Отбор

- Критерий — годовой Sharpe на train: `mean/std·√252` по чистой доходности
  (`calc_sharpe_comm`, `strategies_walkforward.py:1838–1848`).
- Двухпроходный поиск: проход 1 — все сигналы × прореженная сетка RM
  (каждый `len(RM)//72`-й элемент), из лучших берутся 30 уникальных
  сигнальных конфигов; проход 2 — эти 30 × полная сетка RM (655–750).
- Топ-10 по train-Sharpe (`ENSEMBLE_TOP_N = 10`, 82, 752).

### Ансамбль

- `pos_ens = mean_k sign(pos_k)` по 10 конфигам (774–778) — дробная позиция
  ∈ [−1, 1] с шагом 0.1.
- В отключённой версии `walkforward_A_DISABLED` — мажоритарное голосование
  (> 50% в одну сторону → ±1).
- В `strategies_walkforward.py::approach_a_one` — `mean(pos)` (2101), позиции
  там ±1, т.е. то же самое.

### Порог отказа от торговли

- `stage3`: если лучший train-Sharpe < `TRAIN_SHARPE_THRESHOLD = 0.3`
  (81, 755), позиция пары в году = 0.
- `strategies_walkforward.py` (v3): порога отказа **нет** — фильтр
  `Sharpe > 0, MDD > −30%, экспозиция > 5%`, а если не прошёл никто,
  берутся топ-3 любые (2085–2089). То есть всегда торгует.

### Слой риск-менеджмента

RM — неотъемлемая часть каждого конфига A; базовой версии без RM у автора нет.
Сетки (`RM_GRIDS_V3`, 103–128; `TREND_RM_GRID`, 130–155):

- Контртренд (S1, S2), дневки: sl_mult {1,1.5,2,3}·ATR; tp_mult {1.5,2,3,5}·ATR;
  max_hold {10,15,20,30}; breakeven {нет, 1·ATR}; cooldown {0,5}; partial_exit {F,T} — 1024.
- Диапазон (S5, S6), дневки: sl {0.75,1,1.5,2}; tp {0.75,1,1.5,2,3}; max_hold {5,8,10,15};
  breakeven; cooldown {0,5}; time_decay {F,T} — 640; плюс выход при ADX > 30 (жёстко).
- Тренд (S3, S4): начальный SL {2,2.5,3}·ATR × breakeven × cooldown ×
  [трейл fixed_atr/chandelier × trail_n {5,10,15,20} × mult {2,2.5,3} +
  parabolic step {0.01,0.02,0.03} × max {0.1,0.15,0.2}] — 396.
- Часовики: max_hold и cooldown крупнее (30–120 баров, cooldown 9).

Объём перебора на пару и год у S1: 1440 сигналов × ~14 RM в проходе 1
плюс 30 × 1024 в проходе 2 ≈ 50 тыс. бэктестов; по 17 тикерам × 4 годам × 6
стратегиям — миллионы. Поправки на множественное тестирование нет нигде.

Механика SL/TP в движке: уровень проверяется по high/low бара t, но выход
учитывается по close[t] (`pos[t] = 0`, PnL бара t целиком достаётся позиции).
Фактически это «выход по закрытию бара, на котором коснулись уровня», а не
стоп-приказ. Порядок внутри бара: сначала SL, потом TP (консервативно).

## 5. Агрегация

### Три уровня (`stage5_msp.py`)

1. Пара (стратегия × тикер) — описательные метрики.
2. Портфель стратегии — EW по 17 тикерам.
3. МСП — EW по 102 = 6 × 17 парам: сначала позиции усредняются по стратегиям
   внутри тикера (неттинг), затем EW по тикерам (437–440).

### Веса (`stage5b_perstrat_portfolio.py`)

- EW (1/N), InvVol (1/σ_i, нормировка), RiskParity (итеративно, равные
  вклады в риск, long-only), MaxSharpe (SLSQP, long-only, Σw = 1).
- Оценка весов walk-forward: на OOS-доходностях предыдущих лет
  (в файл позиций сохраняются только тестовые годы), поэтому в 2022 —
  всегда EW, в 2023 — веса по одному году OOS 2022 и т.д. Ковариация —
  выборочная + 1e-10·I, без сжатия.
- `stage5c_extended_portfolio.py` добавляет MaxDiv, отбор тикеров
  ALL/POSITIVE/TOP12 и наборы стратегий ALL6/TOP4/NO_S5/DIVERSE3 —
  720 + 160 вариантов.

### Свободный капитал

- Незанятая доля капитала `1 − exposure` получает ключевую ставку ЦБ
  за календарные дни (FDR): `fdr = max(0, 1 − exp)·rf_d·cal_days`
  (`stage5_msp.py:227`).
- При `exposure > 1` — плата за маржу `(ключевая + 2%)/365` (230).
- `total = trading + fdr − margin`; `excess = total − rf·cal_days`.

## 6. Метрики и Sharpe

- **Trading Sharpe**: `mean(net)/std(net)·√252`, без rf и FDR. Используется
  на train.
- **Excess Sharpe**: `mean(total − rf)/std(total)·√252` — числитель избыточный,
  знаменатель от полной доходности (`calc_excess_sharpe`, `stage3:126–161`).
  Используется на test.
- Ещё «Excess @9%» — контрфактическая ставка 9%.
- Аннуализация: дневки √252; часовики в v3 — √(252·9); в финале часовые
  доходности агрегируются в дневные и тоже √252 (`msp_correct.py`, docstring).
- Комиссия: `|Δpos|·comm`, comm = 0.05% (inst) и 0.06% (std), дневки;
  0.04/0.05% — часовики. Переворот ±1 → 2·comm.
- Доходность годовая = сумма лог-доходностей / число лет; MDD — по
  кумулятивной сумме лог-доходностей.
- Win rate: на уровне пары — доля прибыльных сделок (`calc_excess_sharpe`),
  на уровне портфеля — доля положительных дней.
- Сделки в год, экспозиция = mean|pos|.
- В ряде таблиц итоговый Sharpe — **среднее годовых Sharpe** (`np.nanmean`
  по 2022–2025), а не Sharpe всего периода (`stage5_msp.py:337–358`,
  docstring `stage3`).

## 7. Бутстрап

- `stage7_bootstrap.py:60–80` и итоговый `fix_all_bootstrap_ce.py:25–37`:
  **iid-бутстрап** индексов дней (`np.random.randint(0, n, n)`), 10 000
  повторов, seed 42, одинаковые индексы для обеих серий (парный).
- Статистика — разность годовых Sharpe по `excess_ret`.
- p-value = доля бутстрап-разностей ≤ 0 (распределение не центрировано под H0;
  это обращение перцентильного ДИ, а не тест при нулевой гипотезе).
- 42 теста без поправки на множественность.
- CE в `fix_all_bootstrap_ce.py:40–45` — степенная (CRRA) полезность,
  в `stage8_economic.py:82–84` — среднее-дисперсия `252·μ − γ/2·252·σ²`.
  Два разных определения CE в одном проекте.

## 8. Ошибки и что НЕ переносить

### Пункты из CLAUDE.md — проверка

1. **`select_best_phase_per_type`** (`stage3c_bcd_30phases.py:1193–1241`) —
   подтверждаю, и всё хуже, чем «выбор фазы по тестовому году».
   - Для каждой ячейки (стратегия, тикер, год) фаза B/C/D выбирается по
     `sharpe_trading` — это Sharpe на тестовом году (1101, 1108).
   - Стартовое значение `best_sh = a_sh` (1211) — Sharpe A на том же тесте.
     Значит, B/C/D по построению ≥ A в каждой ячейке. ΔSharpe > 0 гарантирован
     селекцией, а не прогнозом.
   - «Оптимизация на train» внутри фаз вырождена: позиции A загружаются только
     для тестового года, на train они нулевые (`build_a_positions_dict`, 230–253).

## 9. Что меняется на крипте

- **Рынок 24/7.** Нет сессий и ночных гэпов. Граница дня для S5 и сессионного
  VWAP в S6 — UTC 00:00. Пивоты дня D строятся по закрытому дню D−1 UTC и
  действуют на всех барах дня D. Сессионный VWAP сбрасывается в 00:00 UTC.
  Нужно решить, что делать с `dev ≈ 0` на первых барах сессии (п. 16):
  минимальное число баров или скользящий VWAP.
- **rf = 0.** Нет FDR, нет платы за маржу, Excess Sharpe = Trading Sharpe.
  Вместо ставки на кэш в PnL входит **funding** перпетуала (у автора аналога нет).
- **Комиссия 0.1% на сторону** — в 2 раза выше, чем у автора (0.05%).
  Высокооборотные конфиги (S5/S6 на часовиках, S1 с малым z_exit) пострадают
  сильнее всего. Ранжирование на train — сразу с комиссией (против п. 8).
- **3 пары вместо 17 бумаг.** Межинструментальной диверсификации почти нет,
  а BTC/ETH/SOL сильно коррелированы. Уровень «портфель стратегии» по 3 парам
  статистически беден. Основной ресурс — смешивание S1–S6. Веса IV/RP/MS
  по 3 активам и 1–2 годам истории — шум. Вселенная зафиксирована решением:
  BTCUSDT, ETHUSDT, SOLUSDT (CLAUDE.md упоминает 4 пары — устарело).
- **Данные Bybit API.** Линейные перпетуалы, last trade, время открытия бара UTC.
  Первые бары (`/v5/market/kline`, проверено 2026-10-01):

  | Пара | launchTime | Первый бар 1d | 1h | 15m | 1m |
  | --- | --- | --- | --- | --- | --- |
  | BTCUSDT | 2020-03-15 | 2020-03-25 | 2020-03-25 10:00 | 2020-03-25 10:30 | 2020-03-25 10:36 |
  | ETHUSDT | 2021-03-15 | 2021-03-15 | 00:00 | 00:00 | 00:00 |
  | SOLUSDT | 2021-10-15 | 2021-10-15 | 00:00 | 00:00 | 00:00 |

  У BTC первый дневной бар неполный (торги с 10:36 UTC) — его отбрасываем.
  Train (до 2023-12-31) по SOL — 2.2 года, по ETH — 2.8, по BTC — 3.8.
  Расширяющийся WF с шагом год даёт на train 1–2 фолда по SOL и ETH.
  Делистинги не попадают в выборку (survivorship).
- **Таймфреймы 1m/15m/1h/1d.** Аннуализация по 365 дням: √365 (1d),
  √(24·365) (1h), √(96·365) (15m). У автора 252 и 9 баров в дне — сетки
  окон нельзя переносить множителем ×9: для 1h это ×24, для 15m — ×96.
  1m — для RV (этап 10) и проверки согласованности, не для торговли
  (комиссия 0.1% съест всё).
- **Объём.** У автора объём в штуках. Для VWAP на крипте — base-объём
  (или turnover/volume в quote — математически то же). Фильтры по объёму
  (`vf_pass`, «объём ниже SMA5») на крипте ведут себя иначе:
  объём 24/7 имеет сильную внутрисуточную и недельную сезонность.
- **Прогрев.** 200 дневных баров на крипте при старте SOL в 2021 году съедают
  большую часть train. Прогрев — по максимальному окну индикатора, не константой.
- **Чистые сигналы.** Фильтры автора (свечи, «сила сигнала», range-фильтр,
  `vf_pass`, ADX, дневной тренд) не переносим. Каждый фильтр — отдельная
  гипотеза на поздних этапах, проверяется против базовой версии.
- **Базовая версия без SL/TP/max_hold — осознанное отличие от автора.**
  У автора риск-менеджмент входит в каждый конфиг A (§4), версии без него нет.
  У нас позиция определяется только машиной состояний стратегии: вход по
  собственному условию, выход по собственному условию выхода (возврат z к
  z_exit, средняя линия Боллинджера, противоположная граница канала,
  разворот Supertrend, возврат к P, возврат к VWAP) или по встречному
  сигналу. Встречный сигнал закрывает позицию, новый вход — только по
  условию входа. Сетка RM добавляется на этапе 4 как гипотеза и
  сравнивается с базой. Следствие: числа автора и наши несопоставимы
  уже на уровне определения стратегии.

## 9a. Почему у автора S1 и S2 различаются, а у нас — нет

S2 (Bollinger: вход за полосой SMA ± k·STD, выход на SMA) по определению
есть S1 (z-score) с порогом выхода 0. У автора стратегии всё же различались
(корреляция S1/S2 ≈ 0.67 — по данным статьи; в репозитории эта цифра не
найдена, `results/final/strategies/correlations/` содержит только средние
корреляции внутри стратегии и между стратегиями по тикеру). Причины различия —
не в самих сигналах:

- разные фильтры входа: у S1 и S2 свои наборы «силы сигнала» (разные
  метрики композита), плюс свечной фильтр, режим волатильности и объём
  (`strategies_walkforward.py:607–730`);
- разный выход: S1 — `|z| < z_exit` (скачок z через полосу выхода не
  закрывает позицию, при z_exit = 0 выход по сигналу невозможен), S2 —
  пересечение SMA (`:661`, `:725–729`);
- RM-сетка (SL/TP/max_hold) в каждом конфиге и отдельный отбор топ-10.

При унифицированных правилах (без фильтров, выход по односторонней границе,
без RM) S2(w, k) ≡ S1(w, z_entry = k, z_exit = 0): на BTC/ETH/SOL 1h train —
0 отличающихся баров. У нас S2 — обёртка над S1, не оптимизируется
и не входит в МСП; эффективных стратегий пять.

## 10. Вывод

Результаты автора — таблицы README, Sharpe подходов A–D, МСП, бутстрап, CE —
**не используются как ориентир для сверки**, включая подход A. Причины:

- отбор параметров и конфигураций на тестовом периоде (§8, п. 1, 2, 5, 11);
- дефекты расчёта: отбор без комиссии, разреженное хранение позиций,
  ошибка знака в корреляциях, дубликаты в сетках (§8, п. 8–12);
- несопоставимый дизайн: MOEX, 17 бумаг, rf > 0 с доходом на свободный
  капитал, RM в каждом конфиге, комиссия 0.05%.

Из репозитория берём только определения сигналов, схему walk-forward,
ансамбль топ-10, трёхуровневую агрегацию и CE. Корректность нашей реализации
проверяется санити-тестами и внутренними инвариантами, а не совпадением
с цифрами автора.
