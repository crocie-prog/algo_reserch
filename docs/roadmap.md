# Дорожная карта

Перенос подхода A из статьи Лысенка (2026) на крипту. Двенадцать этапов от
инструментов до волатильности; каждый заканчивается проверяемым критерием
готовности, и следующий не начинается без него.

**Текущий этап:** 3.

## Этапы

0. **Инструменты.**
    - Git: `clone` репозитория автора, свой репозиторий, коммиты, `.gitignore` для `data/`.
    - VS Code: venv, Jupyter-ноутбуки внутри редактора.
    - Структура: `data/`, `src/`, `notebooks/`, `results/`, `config.yaml`; данные — parquet из Bybit API в `data/raw/`.
    - Готово, когда проект клонируется на чистую машину и запускается одной командой.
1. **Данные.**
    - Загрузчик Bybit API через ccxt: 3 пары (BTCUSDT, ETHUSDT, SOLUSDT) × 1m, 15m, 1h, 1d, UTC, время открытия бара, инкрементальная докачка, без незакрытого последнего бара; функция `load(symbol, tf)`. Парсер для TSLab остаётся отдельно и в исследованиях не используется.
    - Отдельно — история funding.
    - Проверки: пропуски, дубли, нулевой объём.
    - Готово, когда отчёт о качестве данных строится автоматически.
2. **Минимальный векторный бэктестер.**
    - `strategy(df, params) → position ∈ [−1, 1]`; PnL = pos.shift(1) × ret − fee × |Δpos|.
    - Метрики как в табл. 5 статьи: доходность, экспозиция, Sharpe, MDD, win rate, сделок в год.
    - Санити-тесты: buy&hold совпадает с ценой; случайный сигнал ≈ −издержки; сигнал, сдвинутый на −1 бар, даёт подозрительно хороший результат (детектор look-ahead).
    - Готово, когда все три теста проходят.
3. **Стратегии по одной: S1 → S2 → S3 → S4 → S6 → S5.**
    - S1 Z-score: прогрев = окно MA; обязателен порог выхода z_exit, иначе whipsaw около нуля.
    - S2 Bollinger: по сути S1 с другими порогами; измерить корреляцию с S1 до включения в портфель.
    - S3 Donchian: канал по барам до t−1, иначе пробоя нет или он смотрит в будущее.
    - S4 Supertrend: рекурсивное состояние, ATR по Уайлдеру; сглаживание сходится примерно за 3× периода.
    - S6 VWAP: выбрать сессионный (якорь UTC) или скользящий, как у автора; объём в quote.
    - S5 Pivot: уровни от закрытого предыдущего дня, на часовиках переносятся на весь следующий день — классическое место смещения баров.
    - Готово, когда каждая стратегия прошла санити-тесты этапа 2.
4. **Риск-менеджмент (опционально).**
    - SL/TP в ATR, max_hold. Начинать без него.
    - У автора сетка RM умножает пространство поиска в десятки раз — главный источник переподгонки в подходе A.
5. **Подход A.**
    - Сетка → ранжирование по Sharpe на трейне → топ-10 → среднее sign(pos) → порог отказа от торговли.
    - Параллельно — тепловые карты Sharpe по парам параметров.
    - Сравнить ансамбль топ-10 с выбором центра плато.
    - Готово, когда для каждой стратегии есть карта плато и решение, что используется.
6. **Кросс-валидация.**
    - Hold-out (уже есть).
    - Walk-forward: расширяющееся окно (как у автора) против скользящего.
    - Purged K-fold с embargo (López de Prado, AFML, гл. 7) — при перекрывающихся позициях.
    - CPCV: распределение OOS-Sharpe вместо одной цифры, плюс PBO.
    - Готово, когда построен scatter «Sharpe трейн vs Sharpe тест» по всем фолдам.
7. **Агрегация.**
    - Пара → портфель стратегии → МСП.
    - Веса: EW и inverse-vol сначала, risk parity потом, max Sharpe последним и со скепсисом (DeMiguel).
    - Матрица корреляций доходностей шести стратегий.
8. **Статистика сравнения.** См. справочник ниже.
9. **Визуализация.**
    - Кривая капитала и просадки, скользящий Sharpe, доходность по годам.
    - Тепловые карты параметров, корреляционная матрица.
    - Гистограмма бутстрап-распределения ΔSharpe с доверительным интервалом.
10. **Волатильность (потом).**
    - RV из 1m-данных, HAR-RV на крипте.
    - Подходы C и D с выбором фазы и параметров только на трейне.
    - Внешние ряды — по правилам раздела «Внешние временные ряды» в CLAUDE.md.
    - Здесь нужны DM-тест и QLIKE.
11. **Перенос в TSLab.**
    - S1–S4 из кубиков: SMA/StDev, Bollinger, Highest/Lowest со сдвигом, ATR; Supertrend — кастомный блок, если нет встроенного.
    - S5 и сессионный VWAP требуют границы дня — кастомные блоки.
    - Ансамбль из 10 параметризаций в кубиках непрактичен: переносить один набор параметров из центра плато.

## Справочник: статистика сравнения

Для доходностей стратегий основной инструмент — тест Ledoit–Wolf и блочный
бутстрап; DM-тест нужен только для сравнения прогнозов.

| Вопрос | Метод | Как читать | Источник |
| --- | --- | --- | --- |
| Насколько точен Sharpe одной стратегии | Стандартная ошибка Sharpe с учётом автокорреляции | 95% ДИ ≈ SR ± 2·SE; на 2 годах дневок SE порядка 0.7 | Lo (2002) |
| Стратегия X лучше Y по Sharpe | Тест Ledoit–Wolf с HAC-оценкой | p < 0.05 и ДИ ΔSharpe не включает 0 | Ledoit, Wolf (2008) |
| То же без предпосылок о распределении | Стационарный или блочный бутстрап | Длина блока ~ корень из T; iid-бутстрап занижает p | Politis, Romano (1994) |
| Лучшая из N протестированных стратегий не случайна | Deflated Sharpe Ratio | Поправка SR на число попыток N, скошенность и эксцесс | Bailey, López de Prado (2014) |
| То же для набора стратегий против бенчмарка | White Reality Check, Hansen SPA | p ниже порога — хоть одна стратегия лучше бенчмарка | White (2000); Hansen (2005) |
| Вероятность переподгонки процедуры отбора | PBO через CPCV | PBO > 0.5 — отбор хуже случайного | Bailey et al. (2017) |
| Экономическая ценность перехода | ΔCE при γ = 3, 5, 10 | Сколько п.п. годовых инвестор заплатил бы за переход | Fleming, Kirby, Ostdiek (2001) |
| Прогноз волатильности A лучше B | DM-тест на разности QLIKE, поправка Harvey–Leybourne–Newbold | Отрицательная статистика — первый прогноз точнее | Diebold, Mariano (1995) |

Порядок интерпретации:

1. Сколько сделок? Мало сделок — дальше не идти.
2. ДИ Sharpe отдельной стратегии пересекает 0? Тогда сравнение стратегий бессмысленно.
3. Сколько вариантов перебрано? Поправка через DSR или SPA.
4. Плато или пик на тепловой карте?
5. Деградация трейн → тест на scatter из этапа 6.
