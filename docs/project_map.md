# Путеводитель по проекту

Для человека, который не писал этот код. Термины выделены курсивом и
объяснены в [словаре](glossary.md) — ссылка ведёт на нужный раздел.

**Что это за проект.** Проверяем, работают ли шесть простых торговых
стратегий (S1–S6) на криптовалютах. Это перенос части диссертации
Лысенка (2026, российский рынок) на Bybit. Главный принцип: сначала
записываем правила проверки, потом смотрим на результат
([*предрегистрация*](glossary.md#статистика-не-повезло-ли-нам)), и не
трогаем последние два года данных ([*test*](glossary.md#периоды-данных)),
пока весь метод не зафиксирован.

**Где мы сейчас.** Этапы 0–3 и 5–6 выполнены. Итог этапа 5: ни одна
стратегия не прошла заранее заданный порог успеха. Самый устойчивый
сигнал — S4 (Supertrend); идёт проверка гипотезы H2 «S4 работает и на
других монетах» — загружаются данные 10 новых пар. Актуальное состояние —
в [session_notes.md](session_notes.md).

## 2. Модули `src/`

### `src/config.py` — настройки (все этапы)

Читает `config.yaml`, проверяет его и переводит пути в абсолютные.
`load_config()`, `tf_minutes("1h") → 60`, `periods_per_year("1h") → 8760`
(сколько баров в году — для перевода в годовые величины).

### `src/data/` — данные (этап 1)

| Модуль | Простыми словами | Главное |
| --- | --- | --- |
| `bybit.py` | Запросы к бирже: свечи, funding, список контрактов. Никогда не сохраняет незакрытую свечу, повторяет запрос при сбоях биржи | `fetch_klines`, `fetch_funding`, `fetch_instrument_info` |
| `store.py` | Хранение на диске. Пишет «атомарно» (сначала во временный файл), не даёт молча перезаписать данные, если биржа их изменила | `write`, `read`, `last_timestamp` |
| `fetch.py` | Команда загрузки: качает только новое, проверяет, что последняя сохранённая свеча не изменилась | `update_klines`, `update_funding`, `main` |
| `clean.py` | Готовит проверенные данные: отбрасывает неполные свечи; часовые и дневные свечи строит из минутных; помечает простои биржи (`is_downtime`) | `build_clean`, `aggregate_1m` |
| `quality.py` | Отчёт о качестве: пропуски, нулевой объём, выбросы, расхождения между таймфреймами; работает по годам, чтобы хватало памяти | `run_all`, `check_bars_stream` |
| `universe.py` | Таблица пар: когда началась история, с какой даты данные можно использовать (`usable_from`) | `build_universe`, `usable_from` |
| `load.py` | Единственный способ прочитать данные для анализа. По умолчанию **не отдаёт** test (2024–2025): для этого нужен явный флаг | `load`, `load_funding` |
| `select_universe.py` | Отбор 10 новых пар для гипотезы H2 по объёму торгов, без взгляда на цены | `select` |

### `src/backtest/` — бэктест (этап 2)

| Модуль | Простыми словами | Главное |
| --- | --- | --- |
| `costs.py` | Комиссия, проскальзывание, *funding* — сколько стоит каждая сделка | `fee_cost`, `funding_cost` |
| `engine.py` | Сердце [*бэктеста*](glossary.md#бэктест-и-издержки): решение на закрытии свечи действует со следующей свечи; прибыль минус издержки; до `usable_from` позиция обнуляется | `run`, `run_for` |
| `metrics.py` | Метрики из [словаря](glossary.md#метрики): доходность, *Sharpe*, просадка, *экспозиция*, сделки | `metrics`, `trades`, `position_stats` |
| `checks.py` | Ловит [*заглядывание в будущее*](glossary.md#периоды-данных): обрезает данные и проверяет, что прошлые решения не изменились | `truncation_check`, `shift_check` |
| `describe.py` | Описательная сводка стратегии без прибыли: частота сделок, время в рынке, *cost_to_target* | `describe`, `position_agreement` |

### `src/strategies/` — стратегии (этап 3)

Каждая стратегия — функция `signal(данные, параметры) → позиция` (+1, −1, 0)
и `warmup(...)` — сколько свечей нужно на [*прогрев*](glossary.md#периоды-данных).
Описание и статус — в [словаре](glossary.md#наши-стратегии).

| Модуль | Стратегия |
| --- | --- |
| `_common.py` | Общее для всех: «машина состояний» (когда войти, выйти, перевернуться), скользящие окна без учёта простоев биржи, ATR |
| `s1_zscore.py` | S1 — отклонение цены от средней |
| `s2_bollinger.py` | S2 — полосы Боллинджера; по сути S1 (обёртка), в анализе не участвует |
| `s3_donchian.py` | S3 — пробой канала максимумов/минимумов |
| `s4_supertrend.py` | S4 — Supertrend |
| `s5_pivot.py` | S5 — уровни дня (пивоты); закрывает позицию в конце суток |
| `s6_vwap.py` | S6 — отклонение от средней цены дня (VWAP); закрывает позицию в конце суток |

### `src/cv/` — проверка на новых данных (этапы 5–6)

| Модуль | Простыми словами | Этап |
| --- | --- | --- |
| `grid.py` | Считает все варианты параметров стратегии один раз и хранит их результаты | 5 |
| `walkforward.py` | [*Walk-forward*](glossary.md#проверка-на-новых-данных): нарезает *фолды*, выбирает лучшие настройки на прошлом, торгует следующий квартал; правило отказа по *train-DSR* | 5 |
| `stage5.py` | Запуск всего этапа 5 одной командой; базовая линия «как ведёт себя отбор на перемешанных данных» | 5 |
| `report.py` | Итоговые вердикты этапа 5 по заранее заданным правилам | 5 |
| `permute.py` | Перемешивает дни, чтобы получить «данные без сигнала» для сравнения | 5 |
| `diagnostics.py` | Сравнение прибыли до и после издержек по всем настройкам | 5 |
| `cpcv.py` | [*PBO и CPCV*](glossary.md#диагностика-переподгонки-этап-6): насколько выбор настроек — подгонка | 6 |
| `stage6.py` | Запуск этапа 6 | 6 |
| `purged.py` | Заготовка (не реализована) | 6 |

### `src/stats/` — статистика (этапы 5–8)

| Модуль | Простыми словами |
| --- | --- |

## 3. Где результаты и что открыть первым

`results/` не хранится в git: на новом компьютере таблицы пересоздаются
командами из раздела 4. В git — только итоговые документы в `docs/` и журнал
попыток.

| Этап | Где | Открыть первым |
| --- | --- | --- |
| 1 — данные | `results/data_quality_summary.csv`, `results/data_quality.csv`, `data/meta/universe.csv` | `data_quality_summary.csv` — сводка по паре и таймфрейму |
| 3 — стратегии | `results/describe_s*_1h*.csv`, `results/agreement_s3_s4_1h.csv`, `results/match_s3_s4_1h.csv` | таблицы в [session_notes.md](session_notes.md), раздел «Этап 3» |
| 5 — подход A | `results/stage5/<вариант>/` (folds.csv, oos_pairs.csv, scatter.csv), `results/stage5/oos.csv`, `results/stage5/noise/`, `results/stage5/diagnostics/` | **[docs/stage5_verdicts.md](stage5_verdicts.md)** — итоговая таблица |
| 6 — CPCV/PBO | `results/stage6/pbo.csv`, `cpcv_paths.csv`, `lambdas.csv` | таблицы в [session_notes.md](session_notes.md), раздел «Этап 6» |
| Все попытки | `results/trials_log.csv` | — (машинный журнал) |

Имя папки варианта этапа 5: `<таймфрейм>_<схема>_slip<проскальзывание>`,
например `1h_expanding_slip0` — основной вариант.

## 4. Главные команды

Все — из корня проекта. Сначала включить окружение:
`.\.venv\Scripts\Activate.ps1` (PowerShell).

| Что | Команда |
| --- | --- |
| Установить зависимости (новый компьютер) | `python -m venv .venv`, затем `.venv\Scripts\python -m pip install -r requirements.txt` |
| Скачать / докачать данные | `python -m src.data.fetch --config config.yaml` (одна пара: `--symbols BTCUSDT`; без отчёта: `--no-quality`) |
| Отчёт качества (по одной паре, экономно) | `python -m src.data.quality --config config.yaml` |
| Тесты (без интернета) | `python -m pytest` |
| Тесты с реальной биржей | `python -m pytest -m network` |
| Этап 5 целиком | `python -m src.cv.stage5 all` (только вердикты: `... verdicts`) |
| Сравнение до/после издержек | `python -m src.cv.diagnostics gross` |
| Этап 6 | `python -m src.cv.stage6` |
| Описательная сводка стратегии | `python -m src.backtest.describe --strategy s1_zscore --tf 1h --params '{"w": 72, "z_entry": 2, "z_exit": 0.5}'` |

Полная загрузка 1m занимает часы; её можно прерывать — следующий запуск
продолжит с места остановки.
