### Команды на продолжение

Активировать окружение (PowerShell): `.\.venv\Scripts\Activate.ps1`

Докачка по одной паре без проверок (бережёт память), затем отчёт отдельно:

```
.venv/Scripts/python -m src.data.fetch --config config.yaml --symbols ETHUSDT --no-quality
.venv/Scripts/python -m src.data.fetch --config config.yaml --symbols SOLUSDT --no-quality
.venv/Scripts/python -m src.data.fetch --config config.yaml --no-funding
```

Последняя команда для уже скачанных пар только сверит последний бар, докачает
новые закрытые бары и построит clean, `results/data_quality.csv`,
`results/data_quality_summary.csv`, `data/meta/universe.csv`.

Если сверка последнего бара упадёт с RevisionError — биржа пересмотрела бар;
осознанно: `--refetch-last N` (пишется в журнал).

Тесты: `.venv/Scripts/python -m pytest` (офлайн), `pytest -m network` (сеть).

### Открытые вопросы

1. **Память при проверке качества.** `quality.run_all` читает все 1m пары
   целиком (~3 млн строк) и строит агрегаты. Если памяти снова не хватит —
   проверять 1m по годовым партициям.
2. **Лимит запросов.** Bybit часто отвечает 10006 (rate limit) и 10016
   (svc error); повторы справляются, но можно поднять `rateLimit` ccxt,
   чтобы реже упираться в лимит.
3. **CLAUDE.md, раздел «Данные»** описывает путь `data/raw/bybit/<tf>/<SYMBOL>.parquet`
   для всех ТФ; по твоему решению 1m хранится партициями по годам. Нужно
   разрешение на правку CLAUDE.md.
4. **Python 3.12** на машине не установлен (есть 3.13 и 3.14); окружение
   на 3.14 работает. Ставить 3.12 — твоё решение.
5. **Предварительные числа в config.yaml** — пересмотреть на этапах 5–6:
   `min_train_sharpe: 0.3`, `min_trades_per_year` (1h 12, 15m 24, 1d 6),
   `rolling_train_months: 12`, `min_session_bars` S6 (1h 4, 15m 16).
6. В скачанных данных уже есть тестовый период (2024–2025) и 2026 год.
   `load()` отдаёт их только с `allow_test=True`; 2026 вне train и test —
